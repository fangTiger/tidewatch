## ADDED Requirements

### Requirement: 全市场成交流订阅
系统 SHALL 从官方 `perpDexs` 获取可用 HIP-3 dex，以配置 `hip3_dexes` 作为白名单，并分别通过主 dex 与入选 HIP-3 dex 的官方 `meta` 获取未下架币种。系统 SHALL 订阅主 dex 全部活跃币种及配置确认的活跃 HIP-3 dex 的 `trades`，并随元数据集合重建订阅。1,000 个 WS 总订阅上限 MUST 同时计算成交流、核心钱包 `userFills`/`allDexsClearinghouseState` 与 `allMids`；计划集合超限时 MUST 在新增任何订阅前整体拒绝并上报对应 WS 子源失败。每笔成交的吃单方 MUST 按 `side == "B"` 时取 `users[0]`、否则取 `users[1]`。系统 SHALL 按（吃单方, 币种, 3 秒窗口）聚合价格乘数量得到的名义价值。

#### Scenario: HIP-3 白名单与官方元数据取交集
- **WHEN** `hip3_dexes` 同时包含官方 `perpDexs` 已登记的 dex 和不存在的 dex，且 `meta` 中包含已下架币种
- **THEN** 系统只订阅已登记白名单 dex 的未下架币种，并记录被忽略的白名单项

#### Scenario: 总订阅计划原子拒绝
- **WHEN** 成交流计划与现有核心钱包、`allMids` 订阅合计超过 1,000
- **THEN** 系统拒绝整个新增计划、上报对应 WS 子源失败，且不留下部分新增订阅

#### Scenario: 买方吃单识别
- **WHEN** 一笔 `side = "B"` 的成交包含 `users = [buyer, seller]`
- **THEN** 系统把该笔名义价值计入（buyer, 币种, 当前 3 秒窗口）

#### Scenario: 三秒窗口边界
- **WHEN** 同一地址同一币种的两笔成交分别位于相邻 3 秒窗口
- **THEN** 两笔成交不跨窗口合并，各自独立判断 5,000,000 美元发现门槛

#### Scenario: TWAP 全零 hash
- **WHEN** 多笔 TWAP 成交的 hash 均为全 0
- **THEN** 系统仍按成交记录和 3 秒窗口累计，不把所有全零 hash 成交错误去重为一笔

### Requirement: 陌生地址查询门槛与优先级
系统 SHALL 把不在重点层或核心层的地址视为陌生地址，候选地址也包含在内。陌生地址单个 3 秒窗口聚合名义价值不少于 5,000,000 美元时，系统 MUST 以监控预算最高优先级查询其状态。发现资格查询 MUST 与成交触发对账共享监控队列、令牌桶与全局 429 熔断，并默认限制为每分钟 3 次 `clearinghouseState` 查询（最多 6 权重/分钟），达到上限时顺延发现任务，使已就绪热点对账仍可执行。已标记做市/高频的地址，以及一小时内在成交流中吃单超过 300 笔的陌生地址，MUST 跳过资格查询。

#### Scenario: 发现查询不挤占热点对账
- **WHEN** 一分钟内已有 3 个发现资格查询执行且队列同时存在第四个发现任务与已就绪热点对账
- **THEN** 系统顺延第四个发现任务并先执行热点对账

#### Scenario: 候选地址仍可被发现
- **WHEN** 候选地址在 3 秒内对同一币种吃单累计正好 5,000,000 美元
- **THEN** 系统将其作为陌生地址安排最高优先级资格查询

#### Scenario: 高频陌生地址跳过
- **WHEN** 陌生地址一小时内已吃单 301 笔后再次达到金额门槛
- **THEN** 系统不查询其账户状态、不晋升，并记录高频跳过原因

#### Scenario: 已监控地址不重复发现
- **WHEN** 重点或核心钱包在 3 秒内吃单超过 5,000,000 美元
- **THEN** 系统不走新巨鲸资格查询，由现有钱包监控处理其仓位变化

### Requirement: 新巨鲸资格判定
系统 SHALL 在资格查询中检查触发币种仓位名义与合约账户价值；触发币种仓位名义不少于 5,000,000 美元，或合约账户价值不少于 1,000,000 美元，即判定达标。达标地址 MUST 按重点层满额替换规则立即进入重点，并生成一条 B 级 `hl_new_whale` 事件；未达标地址 MUST 缓存 1 小时，期间不再查询。

#### Scenario: 仓位达标而账户价值未达标
- **WHEN** 陌生地址触发币种仓位名义为 5,000,000 美元但合约账户价值低于 1,000,000 美元
- **THEN** 地址仍判定达标、进入重点并生成 B 级 `hl_new_whale`

#### Scenario: 账户价值达标而仓位未达标
- **WHEN** 陌生地址触发币种仓位名义低于 5,000,000 美元但合约账户价值为 1,000,000 美元
- **THEN** 地址仍判定达标、进入重点并生成 B 级 `hl_new_whale`

#### Scenario: 未达标缓存一小时
- **WHEN** 地址首次查询未达标，并在 59 分钟后再次达到成交流金额门槛
- **THEN** 系统不重复查询；满 1 小时后再次触发才可重新查询

#### Scenario: 重点层满额时遵守保护规则
- **WHEN** 新巨鲸达标但重点层已满且最低名义钱包为手动添加
- **THEN** 系统改为替换最低的非手动重点钱包；不存在可替换钱包时保留新地址为候选并记录原因

### Requirement: 发现状态持久化与健康
系统 MUST 只把已达到 5,000,000 美元门槛并进入资格查询或已有处理决定的成交流窗口写入 `hl_state`；低于门槛的窗口 MUST 只在内存中关闭，不得写入发现状态。持久化窗口用于查询游标恢复和重启幂等，默认保留 2 小时；未达标地址缓存仍默认保留 1 小时。两种保留期 SHALL 可配置，系统 MUST 在后台按配置周期删除过期行。必要订阅状态仍写入 `hl_state`。`hl_trades_ws` MUST 独立登记健康状态，消息或 pong 更新成功时间，断线和解析失败上报失败。

#### Scenario: 小额窗口不写发现状态
- **WHEN** 系统关闭大量聚合名义价值低于 5,000,000 美元的成交流窗口
- **THEN** 系统释放这些窗口，且不新增任何 `discovery_window:` 状态行

#### Scenario: 过期发现状态定期清理
- **WHEN** 已处理发现窗口超过配置的 2 小时保留期，或未达标缓存超过配置的 1 小时保留期
- **THEN** 后台清理删除对应状态行，但不删除 `hl_state` 中其他用途的状态

#### Scenario: 重启后不重复发现
- **WHEN** 一个达标窗口已生成 `hl_new_whale`，应用在相同成交回放前重启
- **THEN** 确定性去重与恢复状态共同保证不新增第二条同一发现事件

#### Scenario: 成交流独立异常
- **WHEN** `hl_trades_ws` 断线而核心钱包 WS 与 REST 保持正常
- **THEN** 状态页仅显示成交流子源异常，已有钱包监控继续运行

### Requirement: 发现内存有界
系统 MUST 在固定窗口结束后及时释放聚合窗口。用于一小时高频判断的每地址成交时间 MUST 只保留最近 301 条，并在地址全部记录离开一小时窗口后删除该地址键；进程内窗口幂等索引 MUST 随发现状态保留期淘汰。

#### Scenario: 长时间回放不累积历史计数
- **WHEN** 大量地址的成交及聚合窗口均已离开一小时统计范围
- **THEN** 聚合窗口、过期地址键和其成交时间均已从内存释放，活跃地址的成交时间条数不超过 301
