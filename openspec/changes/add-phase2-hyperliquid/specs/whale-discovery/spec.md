## ADDED Requirements

### Requirement: 全市场成交流订阅
系统 SHALL 订阅主 dex 全部币种及配置确认的活跃 HIP-3 dex 的 `trades`，在 WS 总订阅不超过 1,000 的前提下随活跃市场集合重建订阅。每笔成交的吃单方 MUST 按 `side == "B"` 时取 `users[0]`、否则取 `users[1]`。系统 SHALL 按（吃单方, 币种, 3 秒窗口）聚合价格乘数量得到的名义价值。

#### Scenario: 买方吃单识别
- **WHEN** 一笔 `side = "B"` 的成交包含 `users = [buyer, seller]`
- **THEN** 系统把该笔名义价值计入（buyer, 币种, 当前 3 秒窗口）

#### Scenario: 三秒窗口边界
- **WHEN** 同一地址同一币种的两笔成交分别位于相邻 3 秒窗口
- **THEN** 两笔成交不跨窗口合并，各自独立判断 5,000,000 美元发现门槛

#### Scenario: TWAP 全零 hash
- **WHEN** 多笔 TWAP 成交的 hash 均为全 0
- **THEN** 系统仍按成交记录和 3 秒窗口累计，不把所有全零 hash 成交错误去重为一笔

### Requirement: 陌生地址查询门槛与优先级
系统 SHALL 把不在重点层或核心层的地址视为陌生地址，候选地址也包含在内。陌生地址单个 3 秒窗口聚合名义价值不少于 5,000,000 美元时，系统 MUST 以监控预算最高优先级查询其状态。已标记做市/高频的地址，以及一小时内在成交流中吃单超过 300 笔的陌生地址，MUST 跳过资格查询。

#### Scenario: 候选地址仍可被发现
- **WHEN** 候选地址在 3 秒内对同一币种吃单累计正好 5,000,000 美元
- **THEN** 系统将其作为陌生地址安排最高优先级资格查询

#### Scenario: 高频陌生地址跳过
- **WHEN** 陌生地址一小时内已吃单 301 笔后再次达到金额门槛
- **THEN** 系统不查询其账户状态、不晋升，并记录高频跳过原因

#### Scenario: 已监控地址不重复发现
- **WHEN** 重点或核心钱包在 3 秒内吃单超过 5,000,000 美元
- **THEN** 系统不走新巨鲸资格查询，由现有钱包监控处理其仓位变化

### Requirement: 新巨鲸资格判定
系统 SHALL 在资格查询中检查触发币种仓位名义与合约账户价值；触发币种仓位名义不少于 5,000,000 美元，或合约账户价值不少于 1,000,000 美元，即判定达标。达标地址 MUST 按重点层满额替换规则立即进入重点，并生成一条 B 级 `hl_new_whale` 事件；未达标地址 MUST 缓存 1 小时，期间不再查询。

#### Scenario: 仓位达标而账户价值未达标
- **WHEN** 陌生地址触发币种仓位名义为 5,000,000 美元但合约账户价值低于 1,000,000 美元
- **THEN** 地址仍判定达标、进入重点并生成 B 级 `hl_new_whale`

#### Scenario: 账户价值达标而仓位未达标
- **WHEN** 陌生地址触发币种仓位名义低于 5,000,000 美元但合约账户价值为 1,000,000 美元
- **THEN** 地址仍判定达标、进入重点并生成 B 级 `hl_new_whale`

#### Scenario: 未达标缓存一小时
- **WHEN** 地址首次查询未达标，并在 59 分钟后再次达到成交流金额门槛
- **THEN** 系统不重复查询；满 1 小时后再次触发才可重新查询

#### Scenario: 重点层满额时遵守保护规则
- **WHEN** 新巨鲸达标但重点层已满且最低名义钱包为手动添加
- **THEN** 系统改为替换最低的非手动重点钱包；不存在可替换钱包时保留新地址为候选并记录原因

### Requirement: 发现状态持久化与健康
系统 SHALL 将成交流窗口、未达标缓存、查询游标和必要订阅状态写入 `hl_state`，使重启后不会因相同已结束窗口重复生成新巨鲸事件。`hl_trades_ws` MUST 独立登记健康状态，消息或 pong 更新成功时间，断线和解析失败上报失败。

#### Scenario: 重启后不重复发现
- **WHEN** 一个达标窗口已生成 `hl_new_whale`，应用在相同成交回放前重启
- **THEN** 确定性去重与恢复状态共同保证不新增第二条同一发现事件

#### Scenario: 成交流独立异常
- **WHEN** `hl_trades_ws` 断线而核心钱包 WS 与 REST 保持正常
- **THEN** 状态页仅显示成交流子源异常，已有钱包监控继续运行
